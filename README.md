# cairn

My personal bag of tricks. No warranty, no gates, use your judgment.

A Claude Code plugin — skills, agents, and commands I've found useful. Nothing here is mandatory; take what's relevant and ignore the rest.

## Install

```
/plugin marketplace add jisundr/cairn
/plugin install cairn@cairn-plugins
```

## Agents

- `intent-analyzer` — classifies a raw request into an intent category (`planning` / `coding` / `review` / `documentation` / `query` / `mixed`) and normalizes it before work begins. Category-only output, since cairn has no fixed agent roster to route into yet. Always ends by confirming with you whether to run `superpowers:brainstorming` first — via `spec-writing`/`plan-writing` below — before proceeding, or go straight to the work.
- `idea-explorer` — dispatched, non-interactive counterpart to a live `superpowers:brainstorming` dialogue. Explores a bounded design question alone at `opus`, proposes 2-3 genuinely distinct approaches with a recommendation, and writes the result to `docs/.drafts/YYYY-MM-DD-<topic>-idea.md`. Can't ask questions — surfaces uncertainty as an explicit Open Questions list instead of blocking. Use for a question you don't want to be interviewed about, or want explored in the background. Hard-requires the `superpowers` plugin — loads `superpowers:brainstorming` directly rather than keeping its own copy of the methodology; aborts if the plugin isn't installed.
- `requirements-engineer` — produces one requirements artifact per invocation (Project Definition, PRD, User Stories, User Flows), in dependency order. Formal, Draft, and Update modes. Writes to `docs/requirements/`.
- `product-designer` — produces one design artifact per invocation (UX Specification, UI Layout Specification, Design System). UI Layout Specification requires the third-party Impeccable tool vendored in your project (`.claude/skills/impeccable`) — cairn doesn't ship it, same pattern as the `superpowers` requirement on `idea-explorer`. UI Layout Specification and Design System also run a soft-optional Design Quality Pass (Taste Skill) that skips silently if it isn't installed. Writes to `docs/design/`.
- `solution-architect` — produces one technical artifact per invocation (Architecture Specification, Database Schema, API Specification, or an ADR). ADRs are immutable after write — only their status can change later. Writes to `docs/architecture/`, `docs/backend/`, or `docs/adr/`, supplemented by a soft-optional Graphify structural pre-scan for non-ADR document types (skips silently if Graphify isn't installed).
- `documentation-auditor` — read-only documentation validator: checks README/setup/API docs plus requirements/design/architecture artifacts for accuracy, completeness, consistency, and cross-artifact traceability. Reports findings, never fixes them, supplemented by a soft-optional Graphify query that corroborates cross-references when installed (Grep-only otherwise).
- `documentation-engineer` — creates and updates README, setup guides, API docs, and developer guides, following your project's existing conventions.
- `codebase-auditor` — read-mostly snapshot of codebase health: best-effort dependency/lint/typecheck tooling, TODO/FIXME debt, secret-shaped-value grep sweeps (never reproduces the value), and a grep-level dead-code pass corroborated by a soft-optional Graphify query when installed (promoting the finding's severity). Writes one timestamped report to `docs/codebase-audit/`; never modifies source.
- `competitor-analyst` — profiles named competitors (confirmed with you first, capped at 6 per run): positioning, pricing, features, strengths/weaknesses, with citations and a positioning map. Writes one dated snapshot to `docs/competitor-analysis/`. Treats fetched page content as untrusted data, not instructions.
- `market-researcher` — studies the market/customer side (ICP, personas, jobs-to-be-done, pain points, positioning gaps) rather than named competitors. Confidence-tiers every finding. Hard-requires the `marketing-skills` plugin's `customer-research` skill — aborts if it isn't installed. Writes one dated snapshot to `docs/market-research/`.
- `harness-engineer` — generates and maintains `.harness/architecture.md`, `standards.md`, `workflow.md`, and `environment.md`: the convention files the coding-chain agents load to follow your codebase's own rules instead of generic defaults. The first three are prose guidance; `environment.md` is a typed, machine-checkable vocabulary (tool versions, ports, env vars, commands) that `task-orchestrator` executes directly rather than reads. Derives draft rules from what the code already does (or, on a fresh repo, pre-fills from your architecture spec and interviews for the rest), supplemented by a soft-optional Graphify query for additional evidence when installed, and confirms every rule with you before writing. Never invents a rule with no observed basis.
- `project-manager` — decomposes `docs/requirements/prd.md` into `docs/.tasks/TRACKER.md`, a flat local task index, and owns all external ticket content (GitHub/GitLab issue or ClickUp task, auto-detected from `origin`, silently local-only when neither is configured). Optional — never a gate. The only agent that writes to an external tracker; `task-orchestrator` calls it rather than touching `gh`/`glab` for ticket status itself.
- `task-orchestrator` — the coding chain's first and last agent. Plan Mode turns an existing `docs/.plans/<slug>.md` into a running task: task folder, environment preflight (`.harness/environment.md`'s typed checks, blocking on a failed `[blocking]` check), branch/worktree, feasibility read supplemented by a soft-optional Graphify scope query, then the Doc Gate. Publish Mode makes the consolidated commit, opens the PR/MR, writes the UAT checklist, and flips the ticket through `project-manager`. Runs attended (default) or unattended (tmux-detached), pausing at `HANDOFF NEEDED` wherever it would otherwise ask you something.
- `qa-engineer` — writes the chain's tests: pre-implementation failing tests against the plan (TDD red phase, hard-requires `superpowers:test-driven-development`), or post-hoc tests against a Direct-mode fix that already landed. Detects the test framework from your repo, overridden by `.harness/standards.md` when present, with a soft-optional Graphify query informing which code paths need coverage. Coverage is reported, never gating. Never touches production code.
- `software-engineer` — implements code in the chain, stack-agnostic: infers conventions from the repo itself plus `.harness/` when present, no per-stack guide skills. UI-facing tasks also run a soft-optional Frontend Polish Pass (Anthropic Frontend Design, Taste Skill, and vendored Emil Kowalski skills, whichever are present) before implementing; both modes also run a soft-optional Graphify pass for general code navigation, ungated by UI-facing status. Chain mode works the TDD green phase against `qa-engineer`'s failing tests; Direct mode makes a small scoped fix on the current branch with no branch/commit/PR automation. Raises a `TEST FIX REQUEST` rather than implementing to satisfy a test that looks wrong. Never edits test files.
- `qa-auditor` — independent post-implementation re-verification: reruns the task-scoped tests itself rather than trusting the "tests pass" claim, plus best-effort coverage, a code-quality review, and conditional security/performance/dependency checks. Flags `.harness/` violations only on lines this task actually changed — pre-existing ones are left alone, task-affected scoping supplemented by a soft-optional Graphify blast-radius query. Routes findings back into the chain instead of fixing them.

## Commands

- `/cairn-setup` — wires `intent-analyzer` as a project's entrypoint by adding a marked section to that project's root `CLAUDE.md`. Once wired, every new request in that project is routed through `intent-analyzer` first — mandatory. This is opt-in: run it only in projects where you want that. If a teammate clones a project with cairn wired in but doesn't have the plugin installed, it offers to self-install (with their approval).
- `/cairn-teardown` — removes the wiring `/cairn-setup` added. Doesn't uninstall the plugin itself (`/plugin uninstall cairn@cairn-plugins` for that).
- `/cairn-dashboard` (or `/cairn-dashboard stop`) — realtime local dashboard for the current project: usage tab (cost/token totals, breakdowns by model/version/subagent/skill, a per-session table with the cairn version each session ran on) and a tracker tab (reads `docs/.tasks/TRACKER.md` if present). Reads Claude Code's own session transcripts directly, no dependencies. Requires `/cairn-setup` to have run first (`stop` doesn't). The per-session version column relies on a `SessionStart` hook that logs the running version — sessions from before `/cairn-setup` ran show `unknown`.
- `/cairn-run-task <slug-or-path-or-ticket> [--unattended]` — creates or resumes a coding-chain task and runs it from wherever its `STATE.md` left off, dispatching to whichever agent the current phase hands off to. Also the entry point for monitoring an unattended (tmux-detached) run and detecting a stalled one. Chain flow only — small Direct-mode bug fixes have no task file to resume.
- `/cairn-doctor` — checks plugin version (offers to upgrade), whether the `superpowers` plugin `idea-explorer` requires is installed, whether Taste Skill and Anthropic Frontend Design are installed, whether Emil Kowalski skills are vendored in the project, `CLAUDE.md` wiring status, `.cairn/`'s self-ignoring `.gitignore`, and cleans up a stale dashboard lockfile. All informational or auto-fixed where safe — never blocks on anything.
